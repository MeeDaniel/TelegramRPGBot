# Telegram RPG Core — первая рабочая версия

Независимый от Telegram, HTTP и базы данных Python-пакет с боевой системой.
`main.py` создаёт игрока с экипировкой, локацию, несколько видов монстров и начинает **одну случайную PvE-встречу**. Игрок управляет действиями через терминал; после завершения показываются результат и добыча, затем программа заканчивается.

## Быстрый запуск

**Python 3.10+**, внешние зависимости не нужны.

```bash
python main.py
```

Варианты запуска:

```bash
python main.py --seed 42       # воспроизводимая генерация
python main.py --support       # посох саппорта вместо меча
python main.py --seed 42 --support
```

Меню внутри боя:

- `1` — атака; у саппорта можно выбрать базовую атаку врага или лечение союзника оружием;
- `2` — защита;
- `3` — суперсила (в демо временно увеличивает урон выбранного союзника на 2 будущих хода);
- `4` — зелье (+50 HP, снова доступно с хода N+3, запас ограничен);
- `5` — покинуть бой (в команде оставшимся приходится продолжать без вас);
- `6` — запросить отмену (в одиночном PvE — сразу; в PvP/группе — после согласия всех активных живых игроков).

Ожидания по таймеру нет; монстры выбирают свои действия автоматически и скрыто. Игрок может прервать программу `Ctrl+C`.

## Структура

```text
telegram_rpg/
    models.py     # предметы, инвентарь, участники, бой, действия и события
    engine.py     # проверки, одновременное разрешение, расчёт урона и защиты
    world.py      # монстры, локации, редкость, ИИ и независимые таблицы добычи
    service.py    # работа с персонажем, экипировкой и сражением; in-memory store
main.py           # консольное демо с созданием контента
ARCHITECTURE.md   # UML и архитектурные решения
```

## Инварианты движка

- Базовые константы для всех бойцов: `melee=1`, `magic=1`, `ranged=1`, `max_hp=100`, `defense=0`.
- Характеристики создаются из экипировки плюс временные эффекты. Монстры используют такие же предметы.
- `Attack(WEAPON)` применяет соответствующую типу оружия характеристику. У оружия саппорта этот режим лечит союзника. `Attack(BASIC)` для саппорта атакует врага с **полным итоговым ближним уроном от всей экипировки**, включая оружие.
- Обычная защита берётся только из брони; активная — сумма защиты всех предметов, умноженная на `armor.guard_multiplier`.
- Урон после защиты: `round_half_up(attack * 100 / (100 + max(0, armor_rating)))`. Урон может стать нулём.
- Все атаки и лечение рассчитываются по состоянию в начале хода и сворачиваются в одну сумму для каждой цели; затем HP ограничивается `[0, max_hp]`. Двойная гибель даёт ничью.
- Суперсила демонстрационная: бафф действует со следующего хода; будущую систему произвольных эффектов можно расширить.
- Номер следующего доступного хода для зелья после применения в `N`: `N+3`. Для `N=1` это ход 4.
- HP персонажа не переносится между битвами, но запас расходников сохраняется в инвентаре.
- При победе в PvE отдельная таблица добычи генерирует награды; надетые на монстра предметы сами по себе не выпадают.
- Добыча за завершённый бой выдаётся ровно один раз.

## Что пока демонстрационное или не реализовано

- Только **одна PvE-встреча** в CLI. Боевой движок уже поддерживает несколько участников и две команды, однако отдельного CLI-лобби PvP и групповых рейдов нет.
- Нет реальных Telegram/HTTP/DB адаптеров. `InMemoryStore` хранит всё до завершения процесса. При подключении конкурентного сервера хранилище нужно заменить транзакционным адаптером и добавить сериализацию.
- Без производства: пример контента создаётся в `main.py`, а не загружается из YAML/JSON.
- Суперсилы пока представлены только баффом характеристик; нет фаз боссов, сложных статусов, дебаффов, крафта, торговли и специальных механик аксессуаров.
- В демо все предметы имеют заранее заданные бонусы; генерации случайных свойств отдельного экземпляра нет.
- При командной отмене требуется голос всех активных живых людей; при выходе одного члена команды бой продолжается, если у команды остались участники.
- Эта версия не защищена от одновременных запросов из нескольких процессов; атомарное хранение понадобится при подключении сервера.

## Пример использования как библиотеки

```python
from random import Random
from telegram_rpg import GameService, Attack
from main import create_content, create_player

game = GameService(create_content(), rng=Random(42))
character = create_player(game, support=False)
battle = game.create_pve(character.id, 'forgotten_forest')
hero = next(p for p in battle.participants.values() if p.character_id == character.id)
monster = next(p for p in battle.participants.values() if p.character_id is None)
events = game.submit_action(battle.id, hero.id, Attack(monster.id))
for event in events:
    print(event.text)
```
